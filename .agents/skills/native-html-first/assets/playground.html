Built-in behavior that replaces JavaScript

Modals, overlays, accordions, autocomplete and calculated results all have native versions.

<dialog> + method="dialog"

Replaces a modal component with a focus trap. Escape closes it, the background goes inert, and the backdrop is a pseudo-element.

returnValue: not opened yet

<dialog id="confirm">
  <form method="dialog">
    <p>Delete this item?</p>
    <button value="cancel">Cancel</button>
    <button value="ok">Delete</button>
  </form>
</dialog>
<script>
  confirm.showModal();   // the only script line
</script>
/* Submitting closes it and sets dialog.returnValue. */

popover + popovertarget

Light-dismissible overlays in the top layer. No z-index fights. Click outside or press Escape to close the menu.

Saved. A manual popover stays until you toggle it.

The menu is placed under its button with CSS anchor positioning where supported, and centred otherwise.

<details name="...">

Give several <details> the same name and opening one closes the others.

What counts as exclusive?

Only one member of the group stays open. The browser enforces it.

Does it need a script?

No. The shared name attribute is the whole mechanism.

What about older browsers?

They show independent disclosure widgets, which still work.

<datalist>

Autocomplete suggestions on any input, while free text stays allowed. Try typing a city that is not listed.

    Media and loading

    Format choice, cropping and load priority are declared in markup. The browser decides the rest.

    <picture> + <source>

    Art direction without JavaScript. Resize the window across 700px and the crop switches between wide and square.

    <picture>
  <!-- format negotiation: first supported type wins -->
  <source type="image/avif" srcset="ridge.avif">
  <source type="image/webp" srcset="ridge.webp">
  <!-- art direction: a different crop at a breakpoint -->
  <source media="(min-width: 700px)" srcset="ridge-wide.jpg">
  <img src="ridge-square.jpg" alt="Teal mountain ridge" width="300" height="300">
</picture>
/* The live demo above uses only the media source with inline SVG crops. */

    Native versions usually come with better keyboard handling and screen reader support than a hand-rolled one. Where support is patchy, use the native element as the baseline and enhance it with JavaScript. The chips at the top of the page show what your browser supports today.
